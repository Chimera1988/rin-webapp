Дополнительные проверки после исправлений:

- Полное каноническое ядро характера и anti_patterns присутствуют в активном стабильном prompt; смена темы не меняет его байты.
- Отсутствующая/нечисловая/низкая confidence не становится доверенным фактом; секретные и прототипные пути отвергаются и для записи, и для retraction.
- Checkbox инициативы исходно не отмечен; короткие явные поправки/просьбы забыть допускаются существующим gate извлечения.
- Тревога со смайлом распознаётся как неблагополучие; «не получилось / не сдал / не выиграл» не становятся радостью.
- Полный HTTP chat handler передаёт конец длинного текста и переводы строк; честный ответ о программной природе без `?` требует одного вызова, без fallback/semantic repair.
- Длинная поправка проходит реальную очередь → memory handler → prompt извлечения. OpenAI-ответ подменён: это доказывает передачу текста и применение контракта, не способность модели правильно извлечь факт.

Три исходно падавших тестовых файла имели устаревшие ожидания: начало утреннего окна 08:00 вместо фактического 10:00, вероятность 0.55 вместо фактической 1 и regex «semanticRetries: 0» при существующей условной правке. Ожидания согласованы с исходным runtime; само расписание не менялось. В push-fixtures явное согласие теперь задаётся явно.

Для последующего воспроизводимого сравнения: фиксировать модель и фактически возвращённый model ID, prompt/schema, память, время, параметры и весь transcript; использовать одинаковые сценарии/исходное состояние, не переносить память между независимыми случаями. ## Непроверенные интеграции и оставшиеся недостатки

`OPENAI_API_KEY` отсутствует; реальные ответы, female self-reference, юмор/сарказм, несогласие, длительный эмоциональный разговор, отказ от шаблонов и честное незнание не проверены на модели ни до, ни после. Не создавались новые ключи, сервисы или расходы.

Нет тестовых конфигураций PostgreSQL/Redis/VAPID: реальные архивные SQL-запросы, восстановление на другом устройстве, cron/доставка push и удаление данных в облаке не подтверждены. Имеющиеся тесты этих модулей используют заглушки.

Browser E2E действительно пробовали запустить. В sandbox сервер получил `listen EPERM 127.0.0.1`; разрешённый запуск поднял Chromium, но переход на `http://rin.test:<port>/login.html` вернул страницу прокси `No approved upstream IPv4 address` и timeout login readiness. Проверка интерфейса не прошла; сетевые настройки среды не менялись.

Build-smoke на чистом исходном архиве и после изменений останавливается на отсутствующем `public/avatar.jpg`. Ссылки manifest/sw на удалённые torii-иконки также остаются. Исходный дефект ресурсов не маскировался успешными модульными проверками. После восстановления ресурсов build-smoke нужно выполнить полностью; его последующие стадии сейчас не подтверждены.

Остальные ограничения: объёмный стабильный prompt, эвристические эмоции/retrieval, ограниченный дословный контекст, неполное восстановление всей личности из облака, отсутствие каскадного удаления архивов и потенциальные задержки очереди памяти. Подробности в RIN-AUDIT.md.

## Повторение и применение

В локальной ветке уже находятся исходники и тесты. Инфраструктурные изменения и миграции не нужны. Изменённое начальное поведение: если на сервере/в браузере нет сохранённого `1`, Рин не начинает разговор автоматически. Включение доступно прежним переключателем; ОС-подписка сама по себе не считается согласием.

```bash
node scripts/rin-behavior-audit.mjs /tmp/rin-audit-repeat.json
npm run check
node scripts/check-syntax.js
git diff --check
```

Для воспроизведения baseline в отдельной папке извлечь исходную ревизию `ee9e8ca`, скопировать туда неизменённые `tests/fixtures/rin-audit-scenarios.mjs` и `scripts/rin-behavior-audit.mjs`, выполнить тот же runner. Ожидаемый baseline exit code — 1, результат 31/48. API-дополнения к тестам проверялись после исправлений отдельно, не выдаются за парное измерение качества до/после.

Коммит реализации/проверок: `96f9c08`. Коммит отчётов следует за ним; полный список:

```bash

```
